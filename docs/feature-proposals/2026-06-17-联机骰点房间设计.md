## 1. 背景与目标

### 1.1 现状

截至 2026-06-17，coccard 的骰点功能完全是本地的：

- `DiceRollerWidget`（`lib/app/widgets/dice_roller.dart`）：使用 `dart:math` 的 `Random` 生成 D100 和 3D6 结果，结果仅保存在当前页面的 `State` 中。
- `DiceHistoryController`（`lib/app/setting/dice_history_controller.dart`）：将投骰记录持久化到 `SharedPreferences`（key = `dice_history_local`），最多 50 条，不发起任何网络请求。
- `DiceRollRecord`（`lib/app/data/dice_roll_record.dart`）：包含 `diceType`（String）、`value`（int）、`createdAt`（DateTime）、`note`（String?），有 `toJson/fromJson`。
- `CharacterManager` 中的技能检定：`performSkillCheck`、`applySanityLoss`、`performGrowthCheck` 等方法均在客户端本地使用 `Random` 生成骰面。
- 项目已有 `http: ^1.2.0` 依赖，无其他网络/实时通信依赖。
- 状态管理使用 `Provider`（`ChangeNotifierProvider`）。

在 COC TRPG 跑团场景中，守秘人（KP）和调查员（PL）通常不在同一物理位置，需要一个可信的骰点环境：骰点结果由服务端生成、所有参与者实时可见、结果不可篡改。

### 1.2 目标

一期联机骰点房间应实现：

1. **创建/加入房间**：KP 创建房间并获得房间码，PL 通过房间码加入。
2. **实时同步骰点**：房间内任何成员的投骰结果实时广播给所有在线成员。
3. **服务端生成骰面**：骰面由服务器随机生成并签名，客户端无法篡改。
4. **房间日志**：房间内存完整的投骰历史，新加入成员可拉取历史记录。
5. **角色关联**：投骰时可选择关联当前角色的技能值，自动计算成功等级。
6. **兼容本地**：本地骰点功能不受影响，联机功能为可选增强。

### 1.3 非目标

- 不实现语音/视频/文字聊天（可后续扩展）。
- 不实现角色卡在线编辑或多人协同编辑角色。
- 不实现战斗回合管理、地图共享等桌游功能。
- 不强制要求账号注册（一期使用设备 UUID + 昵称即可）。
- 不替换本地骰点功能，两者并存。

## 3. 架构方案选型

### 3.1 候选方案对比

#### 方案 A：WebSocket 自建服务端

| 维度 | 评估 |
|------|------|
| 实时性 | 优秀。全双工通信，骰点结果毫秒级推送 |
| 成本 | 中等。需要部署和维护一台 WebSocket 服务器（可用 Dart shelf 或 Go/Gin 实现） |
| 复杂度 | 高。需要自行处理连接管理、心跳、断线重连、消息持久化 |
| 可扩展性 | 优秀。架构清晰，可独立扩展服务端 |
| Flutter 集成 | 良好。`web_socket_channel` 包成熟 |
| 离线容错 | 需自行实现断线重连和消息队列 |

#### 方案 B：HTTP 长轮询（Long Polling）

| 维度 | 评估 |
|------|------|
| 实时性 | 差。轮询间隔决定延迟，通常 1-5 秒 |
| 成本 | 低。无特殊服务端要求，普通 REST API 即可 |
| 复杂度 | 低。复用 `http` 包，服务端实现简单 |
| 可扩展性 | 中等。轮询频率高时服务端压力大 |
| Flutter 集成 | 优秀。已有 `http` 依赖 |
| 离线容错 | 差。轮询失败时无法感知新消息 |

#### 方案 C：Firebase Realtime Database / Firestore

| 维度 | 评估 |
|------|------|
| 实时性 | 优秀。SDK 内置实时监听，数据变更即时推送 |
| 成本 | 低（初期）。免费额度 1GB 存储 / 10GB 月传输；超限后按量计费 |
| 复杂度 | 低。无需自建服务端，SDK 处理连接管理、断线重连 |
| 可扩展性 | 优秀。Google 托管，自动扩缩容 |
| Flutter 集成 | 优秀。`firebase_core` + `cloud_firestore` 成熟 |
| 离线容错 | 优秀。Firestore SDK 内置离线缓存，重连后自动同步 |
| 安全规则 | 优秀。Firestore Security Rules 可在服务端层面校验骰面签名 |

### 3.2 推荐方案

**推荐方案 C：Firebase (Cloud Firestore) + Cloud Functions**

理由：

1. **最小基础设施成本**：coccard 是个人/小团队项目，不需要自建服务器。Firebase 免费额度完全覆盖日常跑团使用（一次跑团约 50-200 条骰点记录，每月跑 10 次也远在免费额度内）。
2. **实时性满足需求**：Firestore 的 `onSnapshot` 监听天然支持骰点实时广播。
3. **断线重连开箱即用**：Firestore SDK 内置离线持久化和重连机制。
4. **安全性**：Cloud Functions 可以作为骰点生成的可信后端，Firestore Security Rules 防止客户端伪造骰面。
5. **Flutter 生态成熟**：`cloud_firestore` 和 `firebase_core` 是 Flutter 官方维护的插件。

### 3.3 备选降级方案

如果 Firebase 不可用（网络限制、费用顾虑），可降级到**方案 A（WebSocket 自建服务端）**，使用 Dart 的 `shelf` + `web_socket_channel` 实现轻量服务端，部署到 Fly.io 或 Railway 等免费 PaaS 平台。此方案在任务拆分中标注为"降级路径"。

## 4. 数据模型设计

### 4.1 房间模型（Room）

对应 Firestore collection: `rooms`

```dart
/// 骰点房间。
/// Firestore path: rooms/{roomId}
class DiceRoom {
  /// 房间 ID（6 位大写字母+数字，如 "A3K7BZ"）。
  final String roomId;

  /// 房间名称（KP 自定义，如 "克苏鲁的呼唤 第三团"）。
  final String name;

  /// 创建者用户 ID。
  final String creatorId;

  /// 创建者昵称。
  final String creatorNickname;

  /// 房间状态。
  final DiceRoomStatus status;

  /// 创建时间。
  final DateTime createdAt;

  /// 最后活跃时间（最后一次骰点或成员变动）。
  final DateTime lastActiveAt;

  /// 当前在线成员 ID 列表。
  final List<String> onlineMemberIds;

  /// 检定规则配置 JSON（复用 CheckRuleProfile 的序列化）。
  final Map<String, dynamic>? checkRuleConfig;

  const DiceRoom({
    required this.roomId,
    required this.name,
    required this.creatorId,
    required this.creatorNickname,
    this.status = DiceRoomStatus.active,
    required this.createdAt,
    required this.lastActiveAt,
    this.onlineMemberIds = const [],
    this.checkRuleConfig,
  });

  Map<String, dynamic> toJson() => {
        'roomId': roomId,
        'name': name,
        'creatorId': creatorId,
        'creatorNickname': creatorNickname,
        'status': status.name,
        'createdAt': createdAt.toIso8601String(),
        'lastActiveAt': lastActiveAt.toIso8601String(),
        'onlineMemberIds': onlineMemberIds,
        if (checkRuleConfig != null) 'checkRuleConfig': checkRuleConfig,
      };

  factory DiceRoom.fromJson(Map<String, dynamic> json) {
    return DiceRoom(
      roomId: json['roomId'] as String,
      name: json['name'] as String? ?? '',
      creatorId: json['creatorId'] as String,
      creatorNickname: json['creatorNickname'] as String? ?? '',
      status: DiceRoomStatus.values.firstWhere(
        (s) => s.name == json['status'],
        orElse: () => DiceRoomStatus.active,
      ),
      createdAt: DateTime.tryParse(json['createdAt'] as String? ?? '') ??
          DateTime.fromMillisecondsSinceEpoch(0),
      lastActiveAt: DateTime.tryParse(json['lastActiveAt'] as String? ?? '') ??
          DateTime.fromMillisecondsSinceEpoch(0),
      onlineMemberIds: (json['onlineMemberIds'] as List<dynamic>?)
              ?.map((e) => e as String)
              .toList() ??
          [],
      checkRuleConfig: json['checkRuleConfig'] as Map<String, dynamic>?,
    );
  }
}

enum DiceRoomStatus {
  /// 房间活跃中。
  active,

  /// 房间已关闭（KP 手动关闭或超时自动关闭）。
  closed,
}
```

### 4.3 骰点消息模型（DiceMessage）

对应 Firestore collection: `rooms/{roomId}/dice_messages`

```dart
/// 房间内的骰点消息。
/// Firestore path: rooms/{roomId}/dice_messages/{messageId}
class DiceMessage {
  /// 消息唯一 ID（Firestore auto-generated 或 microsecond timestamp）。
  final String messageId;

  /// 投骰者用户 ID。
  final String userId;

  /// 投骰者昵称。
  final String nickname;

  /// 关联角色名称（可选）。
  final String? characterName;

  /// 骰面类型：'D100'、'3D6'、'1D6'、'2D6' 等。
  final String diceType;

  /// 骰面结果数值（D100 为 1-100，3D6 为 3-18）。
  final int value;

  /// 各骰子单独结果（如 3D6 = [3, 5, 2]，D100 = [47]）。
  final List<int> diceDetails;

  /// 关联技能名称（可选，D100 技能检定时填写）。
  final String? skillName;

  /// 技能目标值（可选）。
  final int? skillValue;

  final String? note;

    required this.nickname,
    this.characterName,
    required this.diceType,
    required this.value,
    this.diceDetails = const [],
    this.skillName,
    this.skillValue,
    this.successLevel,
    this.isSuccess,
    this.note,
    required this.createdAt,
    this.signature,
    this.type = DiceMessageType.roll,
  });

  Map<String, dynamic> toJson() => {
        'messageId': messageId,
        'userId': userId,
        'nickname': nickname,
        if (characterName != null) 'characterName': characterName,
        'diceType': diceType,
        'value': value,
        'diceDetails': diceDetails,
        if (skillName != null) 'skillName': skillName,
        if (skillValue != null) 'skillValue': skillValue,
        if (successLevel != null) 'successLevel': successLevel,
        if (isSuccess != null) 'isSuccess': isSuccess,
        if (note != null) 'note': note,
        'createdAt': createdAt.toIso8601String(),
        if (signature != null) 'signature': signature,
        'type': type.name,
      };

  factory DiceMessage.fromJson(Map<String, dynamic> json) {
    return DiceMessage(
      messageId: json['messageId'] as String? ?? '',
      userId: json['userId'] as String? ?? '',
      nickname: json['nickname'] as String? ?? '',
      characterName: json['characterName'] as String?,
      diceType: json['diceType'] as String? ?? 'D100',
      value: json['value'] as int? ?? 0,
      diceDetails: (json['diceDetails'] as List<dynamic>?)
              ?.map((e) => e as int)
              .toList() ??
          [],
      skillName: json['skillName'] as String?,
      skillValue: json['skillValue'] as int?,
      successLevel: json['successLevel'] as String?,
      isSuccess: json['isSuccess'] as bool?,
      note: json['note'] as String?,
      createdAt: DateTime.tryParse(json['createdAt'] as String? ?? '') ??
```

## 5. API 设计

### 5.1 Cloud Functions（服务端可信逻辑）

骰面生成必须在 Cloud Functions 中执行，确保不可篡改。

#### 5.1.1 `generateRoll`

- **触发方式**：Firestore `onDocumentCreated` on `rooms/{roomId}/roll_requests/{requestId}`
- **输入**：`roll_request` 文档（`userId`、`diceType`、`skillName?`、`skillValue?`、`note?`）
- **逻辑**：
  1. 读取房间配置和检定规则。
  2. 使用 `crypto.randomBytes` 生成真随机骰面。
  3. 若有 `skillValue`，使用房间检定规则计算成功等级。
  4. 使用 HMAC-SHA256 对结果签名（key 存储在 Cloud Functions 环境变量中）。
  5. 写入 `dice_messages` 集合。
  6. 更新房间 `lastActiveAt`。
  7. 删除 `roll_request` 文档。
- **输出**：`dice_message` 文档自动出现在 `dice_messages` 集合中，触发客户端的 `onSnapshot` 实时监听。

#### 5.1.2 `closeRoom`

- **触发方式**：HTTP callable function
- **输入**：`roomId`
- **权限校验**：仅房间创建者（KP）可关闭
- **逻辑**：将房间 `status` 设为 `closed`，写入一条系统消息

#### 5.1.3 `verifySignature`

- **触发方式**：HTTP callable function（可选，客户端怀疑篡改时调用）
- **输入**：`messageId`、`signature`
- **逻辑**：使用服务端 key 重新计算 HMAC，对比是否一致

### 5.2 客户端 API（Firestore 直接操作）

以下操作由客户端直接通过 Firestore SDK 执行，不经过 Cloud Functions。

#### 5.2.1 创建房间

```dart
/// 创建房间并返回房间码。
/// 客户端操作：
/// 1. 生成 6 位房间码（大写字母+数字，排除易混淆字符如 0/O/1/I/L）。
/// 2. 写入 rooms/{roomId} 文档。
/// 3. 写入 rooms/{roomId}/members/{userId} 文档（KP 角色）。
/// 4. 返回 roomId。
Future<String> createRoom({
  required String name,
  required DiceUserIdentity creator,
  Map<String, dynamic>? checkRuleConfig,
}) async {
  final roomId = _generateRoomCode();
  final now = DateTime.now();
  await _firestore.collection('rooms').doc(roomId).set({
    'roomId': roomId,
    'name': name,
    'creatorId': creator.userId,
    'creatorNickname': creator.nickname,
    'status': DiceRoomStatus.active.name,
    'createdAt': Timestamp.fromDate(now),
    'lastActiveAt': Timestamp.fromDate(now),
    'onlineMemberIds': [creator.userId],
    if (checkRuleConfig != null) 'checkRuleConfig': checkRuleConfig,
  });
  await _firestore
      .collection('rooms')
      .doc(roomId)
      .collection('members')
      .doc(creator.userId)
      .set({
    'userId': creator.userId,
    'nickname': creator.nickname,
    'role': DiceRoomRole.keeper.name,
    'joinedAt': Timestamp.fromDate(now),
    'lastSeenAt': Timestamp.fromDate(now),
    'isOnline': true,
  });
  return roomId;
}
```

#### 5.2.2 加入房间

```dart
/// 通过房间码加入房间。
/// 校验：房间存在、状态为 active、成员数未超限（默认 8 人）。
Future<void> joinRoom({
  required String roomId,
  required DiceUserIdentity user,
  int? characterId,
  String? characterName,
}) async {
  final roomDoc = await _firestore.collection('rooms').doc(roomId).get();
  if (!roomDoc.exists) throw DiceRoomException('房间不存在');
  final room = DiceRoom.fromJson(roomDoc.data()!);
  if (room.status == DiceRoomStatus.closed) {
    throw DiceRoomException('房间已关闭');
  }
  if (room.onlineMemberIds.length >= 8) {
    throw DiceRoomException('房间已满');
  }
  final now = DateTime.now();
  await _firestore
      .collection('rooms')
      .doc(roomId)
      .collection('members')
      .doc(user.userId)
      .set({
    'userId': user.userId,
    'nickname': user.nickname,
    'role': DiceRoomRole.player.name,
    if (characterId != null) 'characterId': characterId,
    if (characterName != null) 'characterName': characterName,
    'joinedAt': Timestamp.fromDate(now),
    'lastSeenAt': Timestamp.fromDate(now),
    'isOnline': true,
  });
  await _firestore.collection('rooms').doc(roomId).update({
    'onlineMemberIds': FieldValue.arrayUnion([user.userId]),
    'lastActiveAt': Timestamp.fromDate(now),
  });
  // 写入系统消息
  await _addSystemMessage(roomId, '${user.nickname} 加入了房间');
}
```

#### 5.2.5 拉取历史记录

```dart
/// 拉取房间骰点历史（加入房间时调用，分页加载）。
Future<List<DiceMessage>> fetchDiceHistory({
  required String roomId,
  int limit = 50,
  DateTime? before,
}) async {
  Query query = _firestore
      .collection('rooms')
      .doc(roomId)
      .collection('dice_messages')
      .orderBy('createdAt', descending: true)
      .limit(limit);
  if (before != null) {
    query = query.where('createdAt',
        isLessThan: Timestamp.fromDate(before));
  }
  final snapshot = await query.get();
  return snapshot.docs
      .map((doc) =>
          DiceMessage.fromJson(doc.data() as Map<String, dynamic>))
      .toList();
}
```

```dart
/// 离开房间。
Future<void> leaveRoom(String roomId, String userId) async {
  await _firestore
      .collection('rooms')
      .doc(roomId)
      .collection('members')
      .doc(userId)
      .update({
    'isOnline': false,
    'lastSeenAt': Timestamp.fromDate(DateTime.now()),
  });

  });

/// 心跳（每 30 秒调用一次，更新 lastSeenAt 和 isOnline）。
Future<void> heartbeat(String roomId, String userId) async {
  await _firestore
      .collection('rooms')
      .doc(roomId)
      .collection('members')
      .doc(userId)
      .update({
    'lastSeenAt': Timestamp.fromDate(DateTime.now()),
    'isOnline': true,
  });
}
```

## 7. 安全与防作弊

### 7.1 核心原则

**骰面由服务端生成，客户端无法预测或修改。**

### 7.2 实现方案

#### 7.2.1 Cloud Function 生成骰面

```
客户端 → roll_requests/{requestId} → Cloud Function (onDocumentCreated)
                                          ↓
                                    crypto.randomBytes()
                                    HMAC-SHA256 签名
                                          ↓
                                    dice_messages/{messageId}
                                          ↓
                                    客户端 onSnapshot 推送
```

- Cloud Function 使用 Node.js 的 `crypto.randomBytes()` 生成密码学安全随机数。
- 骰面范围：D100 → `randomBytes(1) % 100 + 1`（注：实际需 rejection sampling 避免偏差），3D6 → 三次 `randomBytes(1) % 6 + 1`。
- 签名算法：`HMAC-SHA256(messageId + diceType + value + userId + createdAt, SECRET_KEY)`。
- `SECRET_KEY` 存储在 Cloud Functions 环境变量中，不暴露给客户端。

#### 7.2.2 Firestore Security Rules

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // 房间文档：只有创建者可修改 status
    match /rooms/{roomId} {
      allow read: if true;
      allow create: if true;
      allow update: if request.resource.data.diff(resource.data)
        .affectedKeys().hasOnly(['status', 'lastActiveAt', 'onlineMemberIds']);

      // 骰点消息：客户端不可写入（只有 Cloud Function 可写）
      match /dice_messages/{messageId} {
        allow read: if true;
        allow write: if false; // Cloud Functions 使用 admin SDK 绕过规则
      }

      // roll_requests：任何已认证用户可创建，不可修改
      match /roll_requests/{requestId} {
        allow create: if true;
        allow read: if true;
        allow update, delete: if false;
      }

      // 成员：用户只能修改自己的文档
      match /members/{userId} {
        allow read: if true;
        allow create: if true;
        allow update: if request.resource.data.userId == userId;
      }
    }
  }
}
```

#### 7.2.3 客户端验签（可选）

客户端收到 `DiceMessage` 后，可以选择性地验证 `signature` 字段。验签需要知道 `SECRET_KEY`，因此一期不暴露给客户端（避免密钥泄露）。改为：

- 信任 Cloud Function 的签名（因为 Security Rules 禁止客户端写入 `dice_messages`）。
- 若用户质疑结果，可请求 KP 在 Firebase Console 中查看原始记录。
- 二期可增加 `verifySignature` callable function，客户端传入 `messageId`，服务端返回 `true/false`。

### 7.3 其他安全措施

| 威胁 | 缓解 |
|------|------|
| 客户端伪造骰面 | `dice_messages` 的 Security Rules 禁止客户端写入 |
| 房间码暴力枚举 | 6 位大写字母+数字 = 约 21 亿种组合，限速 10 次/分钟 |
| 恶意用户刷骰点 | Cloud Function 内限速：同一用户每 3 秒最多一次骰点请求 |
| 房间信息泄露 | 仅持有房间码的用户可加入（无公开房间列表） |
| 重放攻击 | 签名包含 `messageId` + `createdAt`，不可重用 |

## 10. 与本地骰点的兼容性

### 10.1 并存设计

联机骰点和本地骰点完全独立，不互相干扰：

| 维度 | 本地骰点 | 联机骰点 |
|------|---------|---------|
| 入口 | HomePage AppBar 的 `Icons.casino_outlined` | AppDrawer 的「联机骰点」 |
| 骰面生成 | 客户端 `dart:math.Random` | Cloud Function `crypto.randomBytes` |
| 结果存储 | `SharedPreferences`（`dice_history_local`） | Firestore（`rooms/{roomId}/dice_messages`） |
| 数据模型 | `DiceRollRecord`（diceType, value, createdAt, note） | `DiceMessage`（扩展：userId, nickname, skillName, successLevel, signature） |
| 状态管理 | `DiceHistoryController`（ChangeNotifier） | `DiceRoomController`（ChangeNotifier） |
| 角色关联 | 可选写入 `Character.skillCheckRecords` | 可选关联 `characterId` + `characterName` |

### 10.2 共享逻辑

以下逻辑应抽取为共享服务，本地和联机共用：

- **检定判定**：`D100CheckEvaluator`（已在 P2#2 实现），本地骰点和联机骰点使用相同的 `CheckRuleProfile` 判定成功等级。
- **骰面类型**：支持的骰面类型列表（D100、3D6、1D6、2D6 等）统一维护。
- **技能列表**：复用 `SKILL_DEFS` 提供技能检定下拉选择。

### 10.3 数据流转

```
本地骰点: DiceRollerWidget → DiceHistoryController → SharedPreferences
                                                    ↘ (可选) CharacterManager.recordSkillCheck

联机骰点: DiceRoomPage → DiceRoomService → Firestore roll_requests
                                          → Cloud Function → dice_messages
                                          → DiceRoomController → UI
                                          ↘ (可选) CharacterManager.recordSkillCheck
```

### 10.4 迁移策略

- 不修改现有 `DiceRollRecord`、`DiceHistoryController`、`DiceRollerWidget`。
- 联机骰点的新模型 (`DiceMessage`) 是独立模型，与 `DiceRollRecord` 无依赖关系。
- 用户可以选择在联机房间内检定后，手动将结果同步到本地角色记录（通过「记录到角色」按钮）。

## 11. 风险与限制

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Firebase 在中国大陆不可用 | 联机功能完全不可用 | 降级到方案 A（WebSocket 自建服务端），或使用国内替代（Supabase） |
| Cloud Functions 冷启动延迟 | 首次骰点可能延迟 1-3 秒 | 使用 Firebase Blaze 计划（按需付费，冷启动更短）；客户端显示 loading 动画 |
| Firestore 免费额度用尽 | 超出后需付费 | 估算：每月 10 次团 × 200 条骰点 × 1KB/条 ≈ 2MB，远在免费额度内 |
| 匿名用户身份不可靠 | 同一设备重新安装后 userId 变化 | 使用设备 UUID 生成 userId（`device_info_plus`），而非 Firebase Anonymous Auth |
| 成员离线检测不准 | 心跳间隔 30 秒，最长 30 秒延迟 | 接受该延迟，UI 上显示"最后在线: X 秒前"而非即时状态 |
| 房间码冲突 | 6 位码理论上可能重复 | Firestore 写入时校验文档是否已存在；冲突时重新生成 |
| 消息列表性能 | 大量消息时 ListView 性能下降 | 限制显示最近 100 条，更早的分页加载 |
| 本地角色数据不上传 | 房间内无法查看他人角色详情 | 一期仅显示角色名称，二期可选上传角色摘要（属性值+技能值） |
