# 战斗伤害计算器（Combat Damage Calculator）

## 1. 背景

当前 coccard 已有武器管理页面（`WeaponPage`），可以添加、编辑、删除武器，也可以从武器库中选择预设武器。然而在实际 COC 7e 跑团过程中，一次攻击流程涉及多个步骤：

1. 攻击检定（技能 vs D100）
2. 命中部位投骰（1D10 → 身体部位）
3. 伤害投骰（武器伤害 + 伤害加值 DB）
4. 护甲减免（按部位查询护甲值）
5. 最终伤害计算与 HP 扣减

目前这些步骤全部需要玩家手动完成：去技能页投 D100、查规则书命中部位表、手算伤害、手动修改 HP。在战斗频繁的场景下（如遭遇战、追逐战），这个过程非常繁琐，容易出错。

现有的战斗追踪器提案（`docs/feature-proposals/2026-06-18-战斗追踪器.md`）是一个完整的回合制战斗管理系统，适合复杂战斗场景。但大多数 COC 战斗是短暂而致命的——调查员通常只需要快速算出"这一枪打中了没有、打在哪里、扣多少血"。本提案聚焦于这个高频、轻量的单次攻击计算场景。

## 2. 用户故事

### US-1：快速攻击计算
> 作为玩家，当我开枪射击时，我希望一键完成"命中检定 → 命中部位 → 伤害投骰 → 护甲减免 → 最终伤害"的完整流程，不需要分别打开多个页面。

### US-2：护甲按部位管理
> 作为玩家，我希望为角色设置不同部位的护甲值（如防弹衣护躯干 8 点、头盔护头部 6 点），计算器自动按命中部位查询并减免。

### US-3：攻击历史记录
> 作为玩家，我希望每次攻击计算的结果被记录下来，方便回合结束后回顾伤害来源。

### US-4：与现有武器库联动
> 作为玩家，我希望计算器直接使用角色已装备的武器数据（名称、技能、伤害），不需要重新输入。

## 3. 非目标（一期不做）

- 多人战斗回合管理（由战斗追踪器提案覆盖）。
- 自动 HP 扣减（一期仅显示最终伤害，由玩家确认后手动修改 HP，避免误操作）。
- 追击/闪避/反击等对抗检定。
- 弹药消耗自动计算。
- 连续射击/散弹扇形攻击的多次命中计算。

## 4. 数据模型

### 4.1 命中部位表（常量）

```dart
/// COC 7e 命中部位表（1D10）
/// 1-3: 头部   4-6: 躯干   7: 右臂   8: 左臂   9: 右腿   10: 左腿
enum HitLocation {
  head('头部', 1, 3),
  torso('躯干', 4, 6),
  rightArm('右臂', 7, 7),
  leftArm('左臂', 8, 8),
  rightLeg('右腿', 9, 9),
  leftLeg('左腿', 10, 10);

  final String label;
  final int minRoll;
  final int maxRoll;
  const HitLocation(this.label, this.minRoll, this.maxRoll);

  static HitLocation fromRoll(int d10) {
    return HitLocation.values.firstWhere(
      (loc) => d10 >= loc.minRoll && d10 <= loc.maxRoll,
      orElse: () => HitLocation.torso,
    );
  }
}
```

### 4.2 部位护甲值

```dart
/// 角色各部位护甲值（持久化到 Character）
class ArmorValues {
  int head;      // 头部，默认 0
  int torso;     // 躯干，默认 0
  int rightArm;  // 右臂，默认 0
  int leftArm;   // 左臂，默认 0
  int rightLeg;  // 右腿，默认 0
  int leftLeg;   // 左腿，默认 0

  ArmorValues({
    this.head = 0, this.torso = 0,
    this.rightArm = 0, this.leftArm = 0,
    this.rightLeg = 0, this.leftLeg = 0,
  });

  int forLocation(HitLocation loc) => switch (loc) {
    HitLocation.head => head,
    HitLocation.torso => torso,
    HitLocation.rightArm => rightArm,
    HitLocation.leftArm => leftArm,
    HitLocation.rightLeg => rightLeg,
    HitLocation.leftLeg => leftLeg,
  };

  Map<String, dynamic> toJson() => {
    'head': head, 'torso': torso,
    'rightArm': rightArm, 'leftArm': leftArm,
    'rightLeg': rightLeg, 'leftLeg': leftLeg,
  };

  factory ArmorValues.fromJson(Map<String, dynamic> json) => ArmorValues(
    head: json['head'] ?? 0, torso: json['torso'] ?? 0,
    rightArm: json['rightArm'] ?? 0, leftArm: json['leftArm'] ?? 0,
    rightLeg: json['rightLeg'] ?? 0, leftLeg: json['leftLeg'] ?? 0,
  );
}
```

### 4.3 攻击计算结果

```dart
/// 单次攻击计算的完整记录
class AttackResult {
  final String weaponName;
  final int attackRoll;        // D100 攻击投骰
  final int attackTarget;      // 攻击技能值
  final String attackLevel;    // 大成功/极难/困难/普通/失败/大失败
  final bool hit;              // 是否命中
  final int? locationRoll;     // 命中部位 D10（命中时才有）
  final HitLocation? location; // 命中部位（命中时才有）
  final String? damageRoll;    // 伤害投骰详情（如 "1D6+1D4 → 3+2 = 5"）
  final int? rawDamage;        // 护甲减免前伤害
  final int? armor;            // 该部位护甲值
  final int? finalDamage;      // 最终伤害（rawDamage - armor，最低 0）
  final bool impale;           // 是否贯穿（极难成功时武器伤害翻倍）
  final DateTime createdAt;

  Map<String, dynamic> toJson() => { ... };
  factory AttackResult.fromJson(Map<String, dynamic> json) => ...;
}
```

## 5. 控制器/服务层

### AttackCalculator（纯函数服务）

```dart
class AttackCalculator {
  final D100CheckEvaluator _evaluator;
  final Random _random;

  AttackCalculator(this._evaluator, [Random? random])
      : _random = random ?? Random();

  /// 执行完整攻击计算。
  ///
  /// [weapon] - 使用的武器
  /// [rule]   - 检定规则（村规/COC7 默认）
  /// [db]     - 伤害加值（如 "+1D4"、"-2"、"0"）
  /// [armorValues] - 角色护甲值
  AttackResult calculate({
    required CharacterWeapon weapon,
    required CheckRuleProfile rule,
    required String db,
    required ArmorValues armorValues,
  }) {
    // 1. 攻击检定
    final attackRoll = _random.nextInt(100) + 1;
    final attackResult = _evaluator.evaluate(
      target: weapon.skill, roll: attackRoll, rule: rule,
    );
    final hit = attackResult.isSuccess;
    if (!hit) {
      return AttackResult(
        weaponName: weapon.name,
        attackRoll: attackRoll,
        attackTarget: weapon.skill,
        attackLevel: attackResult.level,
        hit: false,
        createdAt: DateTime.now(),
      );
    }

    // 2. 命中部位
    final locationRoll = _random.nextInt(10) + 1;
    final location = HitLocation.fromRoll(locationRoll);

    // 3. 伤害投骰
    final isImpale = attackResult.level == '极难成功' ||
        attackResult.level == '大成功';
    final damageDetail = _rollDamage(weapon.damage, db, isImpale);

    // 4. 护甲减免
    final armor = armorValues.forLocation(location);
    final finalDamage = max(0, damageDetail.total - armor);

    return AttackResult(
      weaponName: weapon.name,
      attackRoll: attackRoll,
      attackTarget: weapon.skill,
      attackLevel: attackResult.level,
      hit: true,
      locationRoll: locationRoll,
      location: location,
      damageRoll: damageDetail.detail,
      rawDamage: damageDetail.total,
      armor: armor,
      finalDamage: finalDamage,
      impale: isImpale,
      createdAt: DateTime.now(),
    );
  }
}
```

## 8. 测试矩阵

### 单元测试（Step 1-2）

1. `HitLocation.fromRoll` 边界值：1→头部、3→头部、4→躯干、6→躯干、7→右臂、10→左腿。
2. `ArmorValues.fromJson` 旧数据缺字段时默认 0。
3. 攻击命中 + 护甲减免：武器伤害 1D10=7，DB +1D4=3，护甲 5，部位躯干 → 最终伤害 5。
4. 攻击未命中：不产生伤害和部位数据。
5. 极难成功触发贯穿：伤害翻倍后再减护甲。
6. 护甲大于伤害时最终伤害为 0（不为负）。

### Widget 测试（Step 6）

7. 攻击弹窗显示武器名称和技能值。
8. 点击攻击按钮后显示结果区域（命中/未命中）。
9. 护甲编辑弹窗可修改并保存。

## 9. 兼容性

- `Character.fromJson` 旧数据缺 `armorValues` 和 `attackLog` 时默认空值，不崩溃。
- 不修改 `CharacterManager.saveCurrentCharacter()` 写入路径（复用现有 `_saveCharacters`）。
- 不新增 SharedPreferences key，数据随角色 JSON 存储。
- `AttackCalculator` 为纯函数，不依赖 UI 或 Provider，可独立单元测试。
- 复用现有 `D100CheckEvaluator` 进行攻击检定判定，规则配置与技能页一致。

## 10. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 伤害表达式（如 "1D6+1D4"、"2D6"、"1D10+DB"）解析复杂 | 可能遗漏某些格式 | 复用 `SanityExpression` 的骰子解析逻辑，补充单元测试覆盖常见武器伤害格式 |
| 贯穿规则仅适用于特定武器（枪械、弓箭等） | 冷武器不应贯穿 | `CharacterWeapon` 增加 `bool canImpale` 字段（默认 false），武器库预设中标记哪些武器可贯穿 |
| 攻击日志膨胀 | SharedPreferences 写入变慢 | 限制最近 50 条，超出自动裁剪 |
| DB 表达式格式不统一（"+1D4"、"-2"、"0"、"none"） | 解析失败 | 统一 DB 格式：正数带 `+`，负数带 `-`，零为 `"0"` |

## 11. 与现有功能的关系

- **武器页（WeaponPage）**：本功能在武器页增加入口，不改变武器管理逻辑。
- **技能检定（SkillPage）**：攻击检定复用 `D100CheckEvaluator`，但不写入技能成长记录（攻击检定不是技能训练）。
- **战斗追踪器提案**：本功能是轻量级单次攻击计算器；战斗追踪器是完整的回合管理系统。两者互补，战斗追踪器可以调用 `AttackCalculator` 作为子模块。
- **SAN 损失**：无直接关系。
- **角色分享码**：`armorValues` 和 `attackLog` 应包含在分享码中（由 `Character.toJson` 自动序列化）。
