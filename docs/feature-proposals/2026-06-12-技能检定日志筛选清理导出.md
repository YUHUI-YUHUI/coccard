# 功能提案：技能检定日志筛选、清理、导出

- **提出日期**：2026-06-12
- **对应 spec 任务**：docs/feedback-development-spec.md 第 5 节 P2#3「检定日志筛选、清理、导出」
- **优先级**：P2（可在 P2#1、P2#2 之后排期）
- **作者**：coccard 每日开发 cron 任务（coccard 0.1）

---

## 1. 背景

截至 2026-06-12，coccard 已在以下位置沉淀技能检定记录：

- `Character.skillCheckRecords` —— 单次技能检定的完整日志（`SkillCheckRecord`），写入 `CharacterManager.performSkillCheck`。
- `Character.skillGrowth` —— 技能成功/失败聚合统计 + 成长标记（`SkillGrowthState`）。
- `DiceHistoryController.records` —— 本地 D100/3D6 投骰历史（`DiceRollRecord`），独立于角色。

当前角色 JSON 在 `SharedPreferences` 中存储，但**玩家没有 UI 入口**去做以下三件事：

1. **筛选**：按技能名 / 成功等级 / 时间区间筛选技能检定日志。
2. **清理**：批量删除指定技能或指定时间的旧日志，控制 SharedPreferences 体积。
3. **导出**：把当前角色的检定日志和成长统计导出成可读文件（CSV / JSON），便于离桌归档或提交给守秘人。

本提案覆盖这一缺口，明确数据模型、UI 入口、控制器、测试矩阵，确保后续 cron tick 可以机械地按文件清单实现。

| 角色 | 故事 | 价值 |

## 3. 范围与非目标

### 3.1 一期范围（本提案）

- 技能检定日志（`SkillCheckRecord`）的**筛选**、**清理**、**导出 CSV**、**导出 JSON**。
- 聚合统计（`SkillGrowthState`）仅在导出 JSON 时一并包含，**不支持单独筛选/导出**。
- 本地骰点历史（`DiceRollRecord`）**不在本提案范围**——它已经是独立控制器，玩家可单独清空/查看。

### 3.2 非目标

- 不实现 PDF 导出（`lib/app/services/pdf_generator.dart` 已存在，但 PDF 排版需要单独设计）。
- 不实现云同步、上传到守秘人服务器、邮件分享等网络功能。
- 不修改 `SkillCheckRecord` / `SkillGrowthState` 数据结构。
- 不影响幕间成长页面（`/skill_growth`）的入口和行为。

## 4. 数据模型

不新增数据类，复用现有结构 + 在 UI 层引入轻量筛选状态对象：

```dart
/// 一期仅作为 UI 层临时状态，不持久化。
class SkillCheckLogFilter {
  final String? skillName;          // null = 全部技能
  final Set<SkillCheckLevel> levels; // 空 = 全部等级
  final DateTimeRange? dateRange;    // null = 不限时间

  const SkillCheckLogFilter({
    this.skillName,
    this.levels = const {},
    this.dateRange,
  });

  bool matches(SkillCheckRecord record) {
    if (skillName != null && record.skillName != skillName) return false;
    if (levels.isNotEmpty && !levels.contains(record.level)) return false;
    if (dateRange != null) {
      final t = record.createdAt;
      if (t.isBefore(dateRange!.start) || t.isAfter(dateRange!.end)) return false;
    }
    return true;
  }

  Map<String, dynamic> toJson() => {
        'skillName': skillName,
        'levels': levels.map((l) => l.name).toList(),
        'dateRange': dateRange == null
            ? null
            : {
                'start': dateRange!.start.toIso8601String(),
                'end': dateRange!.end.toIso8601String(),
              },
      };
}
```

CSV 列（固定顺序）：

```
created_at,skill_name,skill_value,roll,level,final_success,luck_spent,luck_cost,rule_profile_id
```

CSV 头行固定为上述字段，UTF-8 BOM（`\uFEFF`）开头以便 Excel 正确显示中文。

JSON 导出 schema（顶层）：

```json
{
  "schema": "coccard.skill_check_log.v1",
  "exportedAt": "2026-06-12T22:30:00.000Z",
  "character": {
    "name": "调查员姓名",
    "id": "<Character.id>"
  },
  "filter": { "skillName": null, "levels": [], "dateRange": null },
  "records": [ /* SkillCheckRecord.toJson() 列表 */ ],
  "growth": { /* SkillGrowthState.toJson() Map，key=skillName */ }
}
```

## 5. 控制器 / 服务拆分

### 5.1 `SkillCheckLogController`（新文件 `lib/app/setting/skill_check_log_controller.dart`）

职责：
- 持有当前 `SkillCheckLogFilter` 状态 + 当前选中角色（`Character`）。
- 提供 `filteredRecords` getter（运行时计算，避免污染 `CharacterManager`）。
- 提供 `clearFiltered()` 操作：**只删除匹配当前筛选条件的 `SkillCheckRecord`**，不删除聚合统计 `skillGrowth`。
- 提供 `exportJson()` / `exportCsv()` 返回 `String`，由调用方决定写到哪里。

接口签名（草案，**仅供实现参考，最终命名可在实现时微调**）：

```dart
class SkillCheckLogController extends ChangeNotifier {
  SkillCheckLogController({required Character character});

  Character get character;
  SkillCheckLogFilter get filter;
  List<SkillCheckRecord> get filteredRecords;

  void setFilter(SkillCheckLogFilter filter);
  void clearFilter();

  /// 删除匹配筛选条件的检定日志，但保留 skillGrowth 聚合统计。
  /// 返回被删除的条数。
  Future<int> clearFiltered();

  /// 导出当前筛选结果为 CSV 字符串（带 UTF-8 BOM）。
  String exportCsv();

  /// 导出当前筛选结果 + 完整 skillGrowth 为 JSON 字符串。
  String exportJson();

  /// 持久化（删除日志后调用）。
  Future<void> persist();
}
```

> 注意：日志实际上存储在 `Character.skillCheckRecords`，最终持久化应通过现有的 `CharacterManager.save()` 或对应 `SharedPreferences` key 完成。本控制器的 `persist()` 只负责协调，**不要**新增 SharedPreferences key。

### 5.2 不需要新增 `SharedPreferences` key

清理后的 `Character` 通过现有 `CharacterManager` 保存路径写入。导出文件路径由 UI 层决定（一期只导出到剪贴板 + 应用文档目录，二期再考虑 SAF）。

## 10. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 删除日志后无法回滚 | 导出 JSON 必须先于 `clearFiltered()`；UI 顺序：先弹导出菜单，再弹清理确认 |
| CSV 中含逗号 / 引号转义 | 转义规则按 RFC 4180：用双引号包裹含 `,` `"` `\n` 的字段，引号内 `"` 改为 `""` |
| 玩家误删聚合统计 | 本提案不删除 `skillGrowth`，UI 文案明确「聚合统计不受影响」 |
| SharedPreferences 体积超限 | 仅删除日志，不影响聚合；导出后清理；同时给出当前条数提示 |
