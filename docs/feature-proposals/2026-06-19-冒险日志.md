# 冒险日志（Session Journal）功能提案

**提出日期**：2026-06-19  
**对应任务**：P0-P2 全部完成后的新功能提案  
**优先级**：P1（玩家高频需求，数据层改动小，UI 独立）

---

## 1. 背景

coccard 应用目前的角色卡包含 `backstory`（背景故事）和 `notes`（备注）两个自由文本字段，但没有结构化的冒险/会话记录。COC TRPG 的典型游玩流程是：

1. 守秘人（KP）主持一个模组，通常跨 1-3 次会话。
2. 调查员（PC）在会话中发现线索、遭遇怪物、损失理智、结识 NPC。
3. 会话结束后，玩家需要回顾关键事件、待办事项、NPC 信息。
4. 下次会话开始时，快速恢复上下文。

当前痛点：
- `notes` 字段是单一文本框，无法按会话或场景分段。
- 技能检定日志（`SkillCheckRecord`）和理智损失记录（`SanityLossRecord`）各自独立，没有统一时间线。
- 玩家无法标记"这个线索很重要"或"这个 NPC 需要后续跟进"。
- 没有"待办"或"调查方向"的结构化跟踪。

## 2. 用户故事

### 核心故事

| # | 角色 | 故事 | 验收条件 |
|---|------|------|----------|
| US-1 | 调查员玩家 | 我想为每次会话创建一条日志，记录日期、标题和正文，这样我能按时间回顾冒险历程。 | 能创建/编辑/删除会话日志；按时间倒序展示。 |
| US-2 | 调查员玩家 | 我想在日志中附加线索条目（标题 + 内容 + 重要程度），这样关键信息不会淹没在自由文本中。 | 每条会话日志可包含 0-N 条线索；线索有标题、正文、重要/普通标记。 |
| US-3 | 调查员玩家 | 我想在日志中记录遇到的 NPC（名字 + 简述 + 关系），这样下次会话能快速回忆。 | 每条会话日志可包含 0-N 条 NPC 记录；NPC 有名字、描述、关系标签（友好/中立/敌对）。 |
| US-4 | 调查员玩家 | 我想标记"待办事项"或"调查方向"，这样下次会话前能快速看到需要做什么。 | 会话日志可包含 0-N 条待办；待办可勾选完成；有独立的"待办汇总"视图。 |
| US-5 | 调查员玩家 | 我想看到与本次会话关联的检定记录和理智损失记录，这样不需要在多个页面间跳转。 | 会话日志详情页底部展示当日检定摘要（成功/失败/大成功/大失败次数）和理智变化。 |

## 3. 范围与非目标

### 一期范围

- 会话日志 CRUD（创建、读取、编辑、删除）。
- 每条日志包含：标题、日期时间、正文（富文本暂不做，用纯文本 + 换行）。
- 线索条目（Clue）：标题、正文、重要程度（重要/普通）。
- NPC 记录：名字、简述、关系标签。
- 待办事项（Todo）：文本、完成状态。
- 日志列表页（按时间倒序）。
- 日志详情页（查看/编辑）。
- 从 HomePage 或 AppDrawer 入口访问。
- 数据持久化到 SharedPreferences（复用 Character JSON）。
- 旧数据兼容（缺字段时默认空列表）。

### 非目标（一期不做）

- 富文本编辑器（Markdown 或 WYSIWYG）。
- 图片/文件附件。
- 模组分组层级（二期 US-8）。
- 与检定日志/理智记录的自动关联（二期 US-5 需要更复杂的时间匹配逻辑）。
- 云端同步或多人共享。
- 全文搜索（日志量小时不需要，二期可加）。

## 4. 数据模型

### 4.1 SessionJournal（会话日志）

```dart
class SessionJournal {
  final String id;              // UUID
  String title;                 // 会话标题，如"血色庄园·第一幕"
  DateTime sessionDate;         // 会话日期（玩家手动选，默认今天）
  String content;               // 正文，纯文本 + 换行
  List<JournalClue> clues;      // 线索列表
  List<JournalNpc> npcs;        // NPC 列表
  List<JournalTodo> todos;      // 待办列表
  DateTime createdAt;           // 创建时间
  DateTime updatedAt;           // 最后修改时间

  SessionJournal({
    required this.id,
    this.title = '',
    DateTime? sessionDate,
    this.content = '',
    List<JournalClue>? clues,
    List<JournalNpc>? npcs,
    List<JournalTodo>? todos,
    DateTime? createdAt,
    DateTime? updatedAt,
  })  : sessionDate = sessionDate ?? DateTime.now(),
        clues = clues ?? [],
        npcs = npcs ?? [],
        todos = todos ?? [],
        createdAt = createdAt ?? DateTime.now(),
        updatedAt = updatedAt ?? DateTime.now();

  Map<String, dynamic> toJson() => {
    'id': id,
    'title': title,
    'sessionDate': sessionDate.toIso8601String(),
    'content': content,
    'clues': clues.map((c) => c.toJson()).toList(),
    'npcs': npcs.map((n) => n.toJson()).toList(),
    'todos': todos.map((t) => t.toJson()).toList(),
    'createdAt': createdAt.toIso8601String(),
    'updatedAt': updatedAt.toIso8601String(),
  };

  factory SessionJournal.fromJson(Map<String, dynamic> json) {
    return SessionJournal(
      id: json['id'] ?? '',
      title: json['title'] ?? '',
      sessionDate: json['sessionDate'] != null
          ? DateTime.parse(json['sessionDate'])
          : DateTime.now(),
      content: json['content'] ?? '',
      clues: (json['clues'] as List<dynamic>?)
          ?.map((c) => JournalClue.fromJson(Map<String, dynamic>.from(c)))
          .toList() ?? [],
      npcs: (json['npcs'] as List<dynamic>?)
          ?.map((n) => JournalNpc.fromJson(Map<String, dynamic>.from(n)))
          .toList() ?? [],
      todos: (json['todos'] as List<dynamic>?)
          ?.map((t) => JournalTodo.fromJson(Map<String, dynamic>.from(t)))
          .toList() ?? [],
      createdAt: json['createdAt'] != null
          ? DateTime.parse(json['createdAt'])
          : DateTime.now(),
      updatedAt: json['updatedAt'] != null
          ? DateTime.parse(json['updatedAt'])
          : DateTime.now(),
    );
  }
}
```

### 4.3 JournalNpc（NPC 记录）

```dart
enum NpcRelation { friendly, neutral, hostile }

class JournalNpc {
  final String id;
  String name;
  String description;
  NpcRelation relation;

  JournalNpc({
    required this.id,
    this.name = '',
    this.description = '',
    this.relation = NpcRelation.neutral,
  });

  Map<String, dynamic> toJson() => {
    'id': id,
    'name': name,
    'description': description,
    'relation': relation.name,
  };

  factory JournalNpc.fromJson(Map<String, dynamic> json) {
    return JournalNpc(
      id: json['id'] ?? '',
      name: json['name'] ?? '',
      description: json['description'] ?? '',
      relation: NpcRelation.values.firstWhere(
        (r) => r.name == json['relation'],
        orElse: () => NpcRelation.neutral,
      ),
    );
  }
}
```

## 5. 控制器设计

### JournalController

```dart
class JournalController extends ChangeNotifier {
  final CharacterManager _characterManager;

  JournalController({required CharacterManager characterManager})
      : _characterManager = characterManager;

  List<SessionJournal> get journals =>
      _characterManager.character.sessionJournals
        ..sort((a, b) => b.sessionDate.compareTo(a.sessionDate));

  /// 创建新日志
  Future<SessionJournal> createJournal({
    required String title,
    DateTime? sessionDate,
  }) async {
    final journal = SessionJournal(
      id: _generateId(),
      title: title,
      sessionDate: sessionDate ?? DateTime.now(),
    );
    _characterManager.character.sessionJournals.add(journal);
    await _characterManager.saveCurrentCharacter();
    notifyListeners();
    return journal;
  }

  /// 更新日志
  Future<void> updateJournal(SessionJournal journal) async {
    journal.updatedAt = DateTime.now();
    await _characterManager.saveCurrentCharacter();
    notifyListeners();
  }

  /// 删除日志
  Future<void> deleteJournal(String journalId) async {
    _characterManager.character.sessionJournals
        .removeWhere((j) => j.id == journalId);
    await _characterManager.saveCurrentCharacter();
    notifyListeners();
  }

  /// 添加线索
  Future<void> addClue(String journalId, JournalClue clue) async { ... }

  /// 添加 NPC
  Future<void> addNpc(String journalId, JournalNpc npc) async { ... }

  /// 添加待办
  Future<void> addTodo(String journalId, JournalTodo todo) async { ... }

  /// 切换待办完成状态
  Future<void> toggleTodo(String journalId, String todoId) async { ... }

  /// 获取所有未完成待办（跨日志）
  List<({SessionJournal journal, JournalTodo todo})> get pendingTodos { ... }

  String _generateId() => DateTime.now().microsecondsSinceEpoch.toString();
}
```

**注意**：`JournalController` 通过 `CharacterManager.saveCurrentCharacter()` 写入，不新增 SharedPreferences key，复用既有持久化路径。

## 9. 兼容性与迁移

- `Character.fromJson()` 中 `sessionJournals` 缺字段时默认 `[]`，旧数据零影响。
- 不新增 SharedPreferences key，复用 Character JSON 存储路径。
- 日志条数建议上限 200 条（约 2-3 年的周常团），超限时提示清理或导出。
- 不修改现有 `Character` 的 `backstory` 和 `notes` 字段，两者并存。

## 10. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| SharedPreferences 单 key 存储大量日志导致写入变慢 | 低（200 条日志约 100-200KB JSON，远低于 SP 限制） | 监控写入耗时，必要时迁移到文件存储 |
| 纯文本正文无格式支持 | 中（长日志可读性差） | 二期引入简单 Markdown 渲染或分段标题 |
| 待办与日志绑定，无法跨日志排序 | 低 | "待办汇总"视图已提供跨日志聚合 |
| 无全文搜索 | 低（日志量小时列表足够） | 二期可加搜索，复用 `reference_page.dart` 的搜索模式 |

## 11. 与其他任务的依赖关系

- **独立于** P2#3（检定日志筛选/导出）和 P2#4（联机骰点房间）。
- **可复用** 战斗追踪器提案（10.3）中的 `ChangeNotifier` + SharedPreferences 持久化模式。
- **二期增强**：与检定日志关联（US-5）需要 `SkillCheckRecord` 增加 `journalId` 外键，属于数据结构变更，建议在一期稳定后再做。
- **二期增强**：与导出功能整合，复用 `PdfGenerator` 和 CSV 导出基础设施。
